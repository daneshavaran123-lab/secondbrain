# Quickstart: راستی‌آزمایی پیوندها و اعلان‌ها

## پیش‌نیاز

- Postgres محلی (5433) با `backend/src/db/schema.sql`، backend روی 3100 با `NOTIFY_TICK_MS=5000` (تیک کوتاه برای آزمون)،
  build پیش‌نمایش frontend روی 8080، LLM ساختگی (`agent-test/fake-llm.mjs`).
- سرورهای ساختگی برای راه‌های بیرونی، که هر درخواست را ثبت می‌کنند:
  - Web Push: endpoint دستگاه آزمون = `http://127.0.0.1:<port>/push/<name>`
  - FCM: `FCM_API_BASE=http://127.0.0.1:<port>/fcm` و یک `FCM_SERVICE_ACCOUNT` آزمونی (کلید RSA تازه)
  - پیامک: `SMS_API_URL=http://127.0.0.1:<port>/sms`
  - ایمیل: `RESEND_BASE_URL=http://127.0.0.1:<port>/email`
- کلیدهای VAPID آزمونی: `npx web-push generate-vapid-keys`.

## ۱. آزمون‌های سریع

```bash
cd backend && npm test        # schedule (موعد، بازه سکوت، منطقه زمانی)، dedupe key، references (پیوند عنوان‌ها، ref ناموجود)
cd frontend && npx tsc --noEmit -p tsconfig.app.json && npx eslint src && npx vitest run && TZ=Asia/Tehran npx vitest run
npx vite build
```

## ۲. API با سه کاربر (`agent-test/notifications-api.mjs`)

ببینید [contracts/notifications-api.md](./contracts/notifications-api.md).

1. A یادآوری برای ۱۰ ثانیه بعد می‌سازد → پس از یک تیک، یک اعلان `reminder` با `path` درست؛ تیک دوم اعلان دوم نمی‌سازد (SC-003).
2. A جلسه‌ای ۱۵ دقیقه و ۵ ثانیه بعد → اعلان `event`؛ زمان جلسه عقب برود → اعلان زمان قدیم ساخته نمی‌شود، زمان تازه می‌شود (FR-011).
3. یادآوری پیش از موعد حذف → اعلانی نمی‌آید.
4. کار با موعد امروز و ساعت شبیه‌سازی‌شده ۸:۰۰ تهران → `task_due`؛ کار انجام‌شده → نه.
5. A دعوت‌نامه برای ایمیل B → B اعلان `invitation` با مسیر پذیرش می‌گیرد؛ A کاری به B واگذار می‌کند → B `delegated`؛ B آن را
   انجام‌شده می‌کند → A `delegation_status`.
6. B هیچ اعلان A را در `GET /notifications` نمی‌بیند؛ `read`/`DELETE` روی اعلان A → بی‌اثر/404 (SC-004).
7. A یک دستگاه webpush ثبت می‌کند → سرور ساختگی push دقیقاً یک درخواست برای هر اعلان می‌گیرد؛ همان endpoint را B ثبت می‌کند →
   اعلان بعدی A به آن نمی‌رسد؛ پاسخ 410 → دستگاه غیرفعال.
8. تنظیمات: `sms` برای `reminder` بدون شماره → 422؛ با شماره → یک درخواست به سرور پیامک با متن کوتاه؛ نوع خاموش → اعلانی
   ساخته نمی‌شود؛ بازه سکوت → `deliver_after` = پایان بازه و push پیش از آن نمی‌رود (SC-008).
9. `send`: A به B (هم‌سازمان) → 201 و B اعلان با نام A؛ A به C (بی‌سازمان مشترک) → 403؛ B «از دیگران» را خاموش → 403؛
   اعلان بیست‌ویکم در یک ساعت → 429؛ `ref` به سازمانی که B عضوش نیست → اعلان بدون پیوند (SC-007).
10. `read` در یک «دستگاه» → `unread-count` دستگاه دیگر کمتر از ۳۰ ثانیه بعد کم شده (SC-005).
11. دو worker هم‌زمان (دو فرایند backend) → هر اعلان یک بار و هر تحویل یک بار.

## ۳. دستیار

با LLM ساختگی:
1. پرسش درباره «کلاته» → پاسخ `references` دارد؛ هر `ref:` در متن در فهرست هست؛ عنوانی که مدل پیوند نکرده، پیوند شده.
2. مدل `[x](https://evil.example)` و `[y](ref:r99)` بنویسد → هر دو متن ساده (SC-006).
3. «کاری بساز» و تأیید → کارت با «باز کردن» به `/tasks?highlight=<id>`.
4. `notify_user` برای «لیلا» → تأیید لازم؛ برای کسی بیرون از سازمان → `NOT_A_TEAMMATE`.

## ۴. مرورگر (`verify-notifications.cjs`)

1. پاسخ دستیار: کلیک روی نام نیاز → صفحه نیازها با همان کارت برجسته؛ پیوند با Tab و Enter هم کار می‌کند.
2. پیوند به مورد حذف‌شده → «این مورد دیگر وجود ندارد».
3. اجازه اعلان (Playwright `grantPermissions(['notifications'])`) → یادآوری ۱۰ ثانیه بعد → شمارنده زنگوله ۱، اعلان سیستمی
   (`showNotification`) یک بار، کلیک روی اعلان در فهرست → صفحه مورد و شمارنده ۰.
4. اجازه رد شده → یک بار توضیح، اعلان در فهرست می‌آید.
5. صفحه تنظیمات: راه‌ها برای هر نوع، بازه سکوت با فیلد ساعت فارسی، خطای شماره پیامک کنار همان فیلد؛ موبایل ۳۹۰ بدون اسکرول افقی.
