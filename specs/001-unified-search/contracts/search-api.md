# Contract: `GET /search`

جستجو در داده‌های کاربر واردشده. هویت فقط از توکن خوانده می‌شود.

## Request

```
GET /search?q=<text>[&type=<sourceType>][&limit=<n>]
Authorization: Bearer <access token>
```

| پارامتر | الزامی | قاعده |
|---------|--------|-------|
| `q` | بله | متن پرسش؛ پس از یکسان‌سازی و trim دست‌کم ۲ نویسه. بیش از ۲۰۰ نویسه بریده می‌شود |
| `type` | خیر | فقط همین نوع (برای «بیشتر»)؛ نوع ناشناخته → ۴۰۰ |
| `limit` | خیر | تعداد در هر گروه؛ پیش‌فرض ۵، حداکثر ۲۰ |

## Responses

### 200

```json
{
  "query": "کلاته",
  "words": ["کلاته"],
  "total": 3,
  "groups": [
    {
      "type": "need",
      "label": "نیاز اجتماعی",
      "total": 1,
      "items": [
        {
          "id": "xikr0sy8s1q",
          "type": "need",
          "title": "آب شرب روستای کلاته",
          "snippet": "روستای کلاته ۱۲۰ خانوار…",
          "date": "2026-10-28T10:12:00.000Z",
          "path": "/organizational/khadim-e-khalgh/needs?highlight=xikr0sy8s1q",
          "titleHit": true
        }
      ]
    }
  ]
}
```

- پرسش کوتاه‌تر از ۲ نویسه (پس از یکسان‌سازی): `200` با `groups: []`، `total: 0` (خطا نیست).
- گروه بدون نتیجه در پاسخ نمی‌آید.

### 400

```json
{ "error": "نوع جستجو شناخته نشد" }
```

### 401

بدون توکن یا توکن نامعتبر (همان پاسخ `requireAuth`).

## Guarantees

- فقط ردیف‌هایی که کاربر مالک آن‌هاست (FR-008)؛ `total` هم فقط همان‌ها را می‌شمارد.
- متن کاربر فقط به شکل پارامتر به Postgres می‌رسد (`$2` آرایه الگوها)؛ `%` و `_` و `\` گریز می‌خورند.
- شکست یک منبع (مثلاً جدولی که در این نصب نیست) کل جستجو را خراب نمی‌کند؛ آن منبع خالی برمی‌گردد.

## Assistant tool: `search_brain`

همان موتور. ورودی: `query`، `sources` (اختیاری، از `type`های منبع)، `limit` (حداکثر ۲۰). خروجی:
`{ keywords, count, results: [{ source, source_key, id, title, snippet, date, path }] }` که `date` برچسب شمسی است.
اگر شرط «همه کلمه‌ها» نتیجه‌ای نداد، با «هر کلمه» تکرار می‌شود (`match: "any"` در خروجی).
